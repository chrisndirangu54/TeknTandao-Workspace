# Funzi ↔ TeknTandao: parent/student initiated linking

Both systems must be deployed and configured before buttons can complete linking.

## Secure pairing workflow

1. School owner enables Funzi integration with `configureFunziSchoolAccess` (allowed classes and Funzi backend service UID).
2. School administrators provision verified portal access: `students/{studentId}.portalUid` is the student's authenticated TeknTandao UID, or `guardianUid` is the authenticated parent/guardian's UID. An unverified guardian name/email does **not** grant linking access.
3. Signed-in parent/student opens **TeknTandao School Management → Connect Funzi**, enters their student ID, and receives a short-lived pairing code copied to the clipboard. The backend checks their actual student/guardian UID; the 192-bit code expires after five minutes.
4. Signed-in Funzi learner opens **Connect School**, enters workspace ID and pastes the code, then clicks **Connect school account**. This sends their **Funzi Firebase ID token** with the code to the secure cross-project redemption endpoint.
5. The backend verifies that ID token against `FUNZI_FIREBASE_PROJECT_ID`, consumes the code atomically and binds the authenticated Funzi UID to the school student ID. The previous owner-only link operation is now restricted to disabling a link.
6. Funzi's authorized backend can retrieve this student's relevant class curriculum via `funziSchoolFeed`; no whole-class roster or marks are exported.

## Deployment configuration

- Deploy Firebase Functions from TeknTandao. Set server environment variable `FUNZI_FIREBASE_PROJECT_ID` to Funzi's actual Firebase **project ID**, and ensure the server can verify revocation status of Funzi user ID tokens. Avoid hardcoding secrets in browser code.
- Configure Funzi Vite env `VITE_TEKNTANDAO_FUNZI_LINK_URL` to the deployed HTTPS URL of `redeemFunziLinkFromFunzi`. This URL is public but every request requires a valid logged-in Funzi Firebase ID token **and** an unexpired, single-use code generated by an authorized school account.
- Ensure Firestore indexes required by the classroom feed exist and Firebase security rules prevent direct unauthorized access to `funziStudentLinks` and `funziLinkRequests`.
- New linking requires proof of account control in **both** systems. Email matching alone is never used as authentication or consent. An optional verified-email lookup may improve discovery only after consent, but cannot replace dual authentication.
- School owner still needs to verify parental authorization as appropriate for minors. The backend currently trusts pre-provisioned `guardianUid` and `portalUid` fields; link creation will fail if those are absent.

## Current limits

The login-to-login flow is not yet a universal single-sign-on system. It currently needs the user to copy a one-time code, and it does not deploy itself. The curriculum feed remains read-only and excludes names, grades, attendance, payments, medical records and student roster data.

Revocation: use `linkFunziStudent` with `active:false` from the school owner, or disable the Funzi integration globally.

## School partner tutoring packages (separate from student linking)

The School Management dashboard now exposes a **Funzi tutoring** tab for school partners. It copies the authoritative Workspace organization ID and can open Funzi when the Workspace Flutter app is built with:

```bash
flutter build web --dart-define=FUNZI_PUBLIC_URL=https://YOUR_LIVE_FUNZI_HOST
```

A school representative signs into Funzi, selects **Tutoring → School tutoring partner**, provides the school name, their Workspace organization ID and a contact address, and submits an application. Funzi places the application in **pending** status. A Funzi platform moderator must independently verify that the representative has control of the named Workspace organization before approving the school to submit tutoring packages. Publishing individual/group packages requires a second moderation decision. The Funzi MVP does not collect payments or provision video meetings.

**This publisher workflow never grants school access to learner data.** Only the existing dual-authenticated student link and approved class-scoped `funziSchoolFeed` authorize curriculum synchronization to one Funzi learner at a time. School publisher status does not replace student/guardian consent, and gradebooks, rosters, attendance, financial and personal records remain excluded.

Deployment and safeguarded launch requirements are documented in Funzi `docs/TUTORING_MARKETPLACE.md`. The school tab does not claim that the Funzi web host or cloud integration is already deployed.
